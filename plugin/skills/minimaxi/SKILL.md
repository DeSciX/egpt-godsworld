# MiniMaxi — Maxi's three roles, in node

The frame: Tony (the person) gives an outline; Maxi, as JARVIS, builds it. Three roles, three threads,
so the roles stay apart — the verifier wrote none of the code, and the coder set none of the
plan:

The persona rides with KB `GodsWorld` only: a role asking without it (the Owl, on `General`) runs with no persona
and no memories, on the platform and as a local agent alike.

Every role is told the same world frame (`WORLD_FRAME`): the Designer and the Builder in the persona (its generated
WORLD FRAME section), the Owl, who runs without the persona, in its first turn:

> THE WORLD, AS BLOCKS: think of the FRQTL universe the way a player thinks of Minecraft. Every frame is a block, and every frame is a container of frames: a block built of smaller blocks, layer inside layer, down to the fundamental dimension. Translate between this block world and the real one as a player does: pixels and ticks carry no units and no absolute scale, like a Minecraft block, so a pixel is whatever the scene takes it to be. FRQTL packages its own physics: what you see emerges from how frame primitives are arranged and from the universe's level-0 settings (the fundamental dimension it is created on), never from force equations.

All of it is owned by `site/app-assets/maxi-roles.js`; this table and the agent files are generated from it and
the persona (`node scripts/gen-plugin-agents.mjs --write`; never edit them by hand).

Run everything from the egpt-godsworld checkout root, Node 25.

## 1. Start the body (the world and the eyes)

```bash
node minimaxi/body.mjs --port <free port> --scene cl1a-mirror --brain platform   # or --brain none for the local brain
```

Its FIRST stdout line is JSON `{bridge, port, scene, mode, brain}`. Keep the process running; stop it with
SIGTERM by its pid when the loop is done. Never use ports 5173, 5530, 5540, 5591, 5594. A hand by hand:
`node minimaxi/hand.mjs --bridge <bridge> inventory '{}'` (exit 0: the result JSON; exit 1: the refusal).

## 2a. One loop on the platform brain

```bash
node minimaxi/loop.mjs --bridge <bridge> --brain platform --outline "a laser hitting a mirror at 30 degrees" --max-rounds 3
```

Each role is a thread of the egpt-godsworld app, asked through the body's ask door with its own KB list (the
table above). The persona rides with KB `GodsWorld` only, so the Designer and the Builder run under it and the
Owl, on `General`, does not. This uses the DeSciX CLI under the hood: one CLI call
at a time on the machine, never `descix login`, never `DESCIX_API_URL`. Threads are kept SHORT on
purpose: a clip's media tokens (~59 per clip-second) are billed again on every later turn of the thread that
saw it, so the Owl gets a fresh thread for every verdict.

## 2b. One loop on the local brain (this Claude session runs the three agents)

```bash
node minimaxi/body.mjs --port <free port> --scene cl1a-mirror --brain none          # in the background
node minimaxi/loop.mjs --bridge <bridge> --brain local --outline "a laser hitting a mirror at 30 degrees"   # in the background
```

The loop writes one TURN FILE per turn, `minimaxi/out/turns/<run>/<n>-<role>.md`, and waits for
`<n>-<role>.answer.md` beside it (it prints the path it is waiting on to stderr). Each turn file's title names
its agent and its THREAD. Map threads to agents exactly as the platform maps them to interaction ids:

- the FIRST turn of a thread: spawn its agent (`maxi-designer`, `maxi-builder` or `maxi-owl` — or a general agent
  told to read `plugin/agents/maxi-<role>.md` and adopt it) with a prompt naming only the two paths:
  > Your turn file is <turn file>. Write your whole reply to <answer file>.
- every LATER turn of the same thread (the Builder's hand results): send the SAME agent the next two paths, so
  the Builder remembers its plan and its earlier clips, as its platform thread does;
- every Owl verdict is a NEW thread (`<run>-owl-r<n>`): a fresh agent each time.

Give an agent nothing else: never show the Owl the plan, the Builder's turns or the memories, and never let
the agent that built a clip judge it. The Builder's and the Owl's footage is a list of frame PNGs in the turn
file (sampled from the clip, in order); the agents open each with Read. Then wait for the next turn file.

## 3. Where things land

- `minimaxi/out/runs/<run>.json`: the report. It holds every turn's text and reply, every hand with its
  result or refusal, each round's clip, prediction and verdict, the threads (interaction ids or turn files)
  and, on the platform, each thread's summed usage. The platform run also prints the cost per thread.
- Clips and frames: under `minimaxi/out/` (the body's paths, named in each footage hand's result).
- On approve: a seen-memory DRAFT `kb/GodsWorld/memories/mm-<scene>-<run>-seen.md`, with its clip and three
  stills in `site/memories/mm-<scene>-<run>/`, written by `scripts/gen-memories-seen.mjs` only with a look:
  its `looked:` line names, by role, who looked at the stills. On the local brain the approving Owl is that look
  (`maxi-owl`, its frames, its turn file and seen account). On the platform brain the approve writes NO memory, only
  `minimaxi/out/runs/<run>.record.json` and, in the report's `awaitingLook`, the stills and the command a human
  (or the seat) runs after looking: `node scripts/gen-memories-seen.mjs <record> --looked-by human:<role>
  --stills <N> --account "<contact, after, passes>"`, where `<role>` is a role in lowercase kebab words
  (`lab-owner`, `godsworld-seat-author`), never a person's name. The platform brain is never a looker. Run the memory
  gate (`node --test "scripts/**/*.test.mjs"`) before keeping it. It is a draft: whether it joins the KB is
  the owner's call.
- A stop is loud: exit 1, the reason on stderr, and the report's `outcome` reads `STOPPED: …`. A malformed
  hand-off, a clip the Builder never described, a `json:done` before any clip, a clip outside 5–10 s, too many
  Builder replies in a round, or a revise on every round all stop it. The turn order and these rules are
  `site/app-assets/maxi-loop.js`, the same loop the lab page runs; `minimaxi/loop.mjs` drives it.
