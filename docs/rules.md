# Rules this repo applies

Each line is a rule as Maxi's lab and its seat apply it today. Rulings and their wording are kept in private records, never in this repo.

- Maxi's eyes are video only: every reading is a 5 to 10 second MP4 clip filmed through FrqtlVision's mediabunny recorder, a drag runs over ticks inside a recording so its effect is watched, the proof runs on 2D scenes first, nothing stands in for the footage (no stills, numbers or text), memories are whole richly commented sketches with no size limit, and the published @descix/frqtl-web spec (and @descix/frqtl-node for MiniMaxi in node) is canonical while every recipe lives here as Maxi's own knowledge
- Maxi works as three roles on three threads, each with its own interaction id: the Designer (Maxi, JARVIS to the user's Tony Stark) plans from the memories and speaks to the user, the Builder implements and hands back a clip, and the Owl verifies from the outline, the prediction and the footage alone; the loop needs no human click, the conversation carries words and clips, never code, and a clip reaches Maxi as `media[]` on the page's own question call
- The seat that builds Maxi works in a private R&D playground and ships to this repo
- Maxi follows the sketch-project paradigm with the names `parts`, `exp.declare`, `exp.setDeclared` and `frqtl.json`; the design is docs/concepts/maxi-sketch-projects.md
- A seen memory is kept only when a human, the local Owl or the seat's own local agent looked at its stills, named on a `looked: <human|local-owl|seat> <role> on <N> stills of memories/<id>/<clip>.mp4 — <account>` line, the looker named by a role (lowercase kebab words such as lab-owner or godsworld-seat-author), never by a person's name; the platform brain's approve alone writes nothing (owner: scripts/gen-memories-seen.mjs; gate: scripts/test/memories.test.mjs)
- A Record is a folder in the shape of the sketch-projects design §6 (docs/concepts/maxi-sketch-projects.md §3) spanning ONE booted world, assembled by the lab from what a run holds: parts.before/after.json are the sketch's `parts` block when the world's Record opens and closes, project/ the sketch as exp.toSketch() holds it at close; a value the run cannot state is never written in its place (a sketch with no `parts` block yields no parts files); a placeholder value in any of its JSON files, and a project entry that is empty, parses as JSON, is a bare `*`, uses the placeholder key `unavailable` as an object key anywhere in its text, or has no line starting `export default function buildExperiment(` (the owner's SKETCH_FORM), are refused by name, and such a folder is not a complete Record (owner: site/app-assets/maxi-record-folder.js; gate: scripts/test/record-folder.test.mjs)
- A seen memory from a run is generated from the run's hand-back Record (`minimaxi/out/<run>/record/`, named by its lab.json): its change rows are the memo lines and its clips the cited clips; only a complete Record is published into kb/GodsWorld/memories and site/memories (the whole folder served), an incomplete one is refused naming every missing field and its draft is written under `minimaxi/out/<run>/memory/` only (owner: scripts/gen-memories-seen.mjs; gate: scripts/test/seen-memory.test.mjs and scripts/test/memories.test.mjs)
- A build memory's `// memo:` lines and extrapolate notes move only in a maxi-memory-curator commit that moves their pins (gate: scripts/test/memories.test.mjs `MEMO_PIN`, `NOTE_PIN`)
